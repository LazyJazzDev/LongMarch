GET STARTED

安装和使用。

CMake + Ninja + vcpkg。先准备工具链，再获取带 LFS 素材的完整源码。

CMake ≥ 3.25C++17 编译器NinjaGit LFSvcpkgSlang ≥ 2026.18.1
01

准备平台工具

macOS / Apple Silicon

安装 Xcode Command Line Tools，以及 CMake、Ninja、Git LFS。原生 Metal 后端需要 macOS 13+；Slang 预编译包可能要求更高版本。

xcode-select --install
brew install cmake ninja git-lfs

Windows

安装 Visual Studio 2022 的“使用 C++ 的桌面开发”、Windows SDK、CMake、Ninja 和 Git LFS。在 x64 Native Tools 命令行中构建。Vulkan 后端另需 Vulkan SDK。

Linux

准备 GCC 或 Clang、CMake、Ninja、Git LFS 和 Vulkan SDK。按发行版安装 GLFW 所需的 X11 / Wayland 开发依赖；确保显卡驱动支持 Vulkan。

依赖由 vcpkg 清单管理。先安装并 bootstrap vcpkg；Slang 默认通过清单特性提供。

02

获取源码和素材

git lfs install
git clone --recurse-submodules https://github.com/LazyJazzDev/LongMarch.git
cd LongMarch
git -C assets lfs pull

已有工作副本：执行 git submodule update --init --recursive 和 git -C assets lfs pull。素材使用仓库固定的子模块版本，不使用 --remote 更新。

03

配置 Release 构建

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DVCPKG_PATH=/path/to/vcpkg -DLONGMARCH_DISABLE_PYTHON=ON -DLONGMARCH_ENABLE_METAL=ON -DLONGMARCH_DISABLE_VULKAN=ON

将 vcpkg 路径替换为本机路径。示例关闭可选 Python 绑定；CUDA 由工具链检测，可用 -DLONGMARCH_DISABLE_CUDA=ON 关闭。更换生成器或工具链时使用新的构建目录。

04

编译并运行第一个样例

cmake --build build --target demo_graphics_hello
./build/demo/graphics_hello/demo_graphics_hello --module triangle

Windows 下运行对应的 .exe。Ninja 默认构建不包含样例与测试，需显式指定目标。用 --list 查看 Graphics Hello 的模块。

Grassland · 基础设施

跨平台资源与命令接口，以及可独立使用的数学、几何和物理计算工具。

graphics::Core / CommandContext

设备、资源与命令

图形层将设备选择、资源创建与命令提交收敛到统一接口。上层绘制、渲染器和计算样例共享同一组抽象。

  • Core 创建 Buffer、Image、Sampler、Shader、Program 和 CommandContext，管理在途帧并查询设备能力。BufferRange 用于描述缓冲区中的资源区间。
  • Program、ComputeProgram、RayTracingProgram 分别承载光栅、计算与 RT 程序；CommandContext 记录资源操作、绘制、计算和追踪命令，再交给 Core 提交。
  • 加速结构接口覆盖底层几何 BLAS 和顶层实例 TLAS；完整 RT pipeline 与 inline ray query 是分别查询的能力，不能互相替代。

适合：自定义渲染器、计算着色器、离屏渲染。资源需保持存活到 GPU 使用完成。

graphics::backend

Metal / Vulkan / D3D12

三个后端实现相同图形接口，并在设备初始化阶段暴露实际支持的能力。

  • Metal 使用原生 metal-cpp，支持光栅、计算、MRT、深度、混合、数据传输和支持设备上的 ray query；没有 RT pipeline / SBT 或 geometry shader。
  • Vulkan 提供跨平台实现，窗口与扩展随平台选择。D3D12 面向 Windows；二者的 RT 和 ray query 都依赖具体硬件、驱动与扩展。
  • CUDA 互操作接口包含共享缓冲和执行屏障，只有启用 CUDA 并有相应后端支持时可用；不能据此推断 Metal 支持 CUDA。

适合：同一应用的多后端部署。请先查询能力，再选择功能。

Shader / VirtualFileSystem

着色器编译与资源打包

统一着色器入口以 Slang 为基础，并允许从字符串或虚拟文件系统编译带指定入口点和参数的程序。

  • Slang 最低版本为 2026.18.1。着色器源文件可打包进 VirtualFileSystem，避免运行时完全依赖工作目录中的散落文件。
  • Metal 使用 Slang → SPIR-V → SPIRV-Cross → MSL → 运行时编译的路径；其他后端选择对应的目标表示。
  • PACK_SHADER_CODE 将工程中的着色器资源接入构建。外部着色器、ray query 和非一致资源索引都有对应示例或检查。

适合：共享着色器逻辑、嵌入式资源和自定义着色器实验。编译成功仍需满足设备功能要求。

Window / window_gestures

窗口、输入与 HDR

窗口层连接平台窗口、图形呈现和输入事件，为原生交互样例提供统一入口。

grassland::Mesh / math

数学、网格与碰撞

数学模块包含线性代数辅助、几何基元、网格处理、距离计算与碰撞检测，是渲染和求解器共用的基础。

  • 提供 AABB、射线、三角形、多项式求根、SVD 与正定投影等工具；静态碰撞和连续碰撞检测（CCD）有独立实现与测试。
  • Mesh 保存位置、法线、UV、切线、颜色和索引，支持 OBJ 读写、顶点拆分/合并、法线和切线生成、球体生成与变换。
  • MeshSDF 提供网格有符号距离查询，并可查询导数；包含主机数据和启用 CUDA 时的设备数据表示。

适合：几何预处理、碰撞实验和可微几何。输入网格质量与具体算法假设仍需由调用方保证。

BVHHost / BVHCuda / BVHRef

空间加速结构

BVH 将包围盒组织成层次结构，为几何查询减少需要访问的候选对象。

  • BVHHost 接收 AABB 和实例索引构建节点，支持更新实例数据，并提供轻量 BVHRef 供遍历代码访问。
  • BVHCuda 将主机 BVH 的节点存入设备容器，向 CUDA 计算提供相同的引用表示；当前这一路径从主机构建结果创建设备树。
  • 它是通用软件空间结构。graphics 的硬件 BLAS / TLAS 和 Sparkium 的计算追踪路径各有自己的资源与执行实现。

适合：主机 / CUDA 几何查询。CUDA 版本需相应工具链与设备。

grassland / physics/diff_kernel

可微物理计算核

一组能计算函数值、Jacobian 和 Hessian 的几何与弹性能量核，便于组装数值优化和物理求解器。

  • 基础函数覆盖行列式、向量长度、归一化、点积、叉积、Atan2 与函数组合；HessianTensor 表达高阶导数数据。
  • 几何核包含点、球、线段、胶囊、立方体、平面等 SDF，以及二面角和二面角能量。
  • 有限元工具提供三角形、四面体的形变梯度和 Neo-Hookean 系列弹性能量。测试目录包含基础函数、组合函数、SDF、FEM 和弹性模型的导数验证。

适合：可微仿真、能量最小化与求解器原型。这些是计算核，时间积分和全局求解需另行组织。

util / FrameProfile

采样、事件与诊断

通用工具为样例和底层系统提供采样、时间、事件、资源与日志支持。

  • Sobol 低差异采样使用方向数素材，并有对应单元测试；素材缺失会报告错误，因此首次克隆必须拉取 LFS 资源。
  • EventManager、延迟处理、计时器、节拍器和 FPSCounter 用于事件连接、生命周期处理和交互循环；另有日志、文件探测与字符串转换工具。
  • FrameProfile 提供选择性开启的 CPU / GPU 帧分析。GPU 时间戳目前只支持 Vulkan，并须等待 GPU 完成后读取；CPU 计时可用于其他后端。

适合：采样器、应用循环和性能诊断。嵌套计时的包含关系需要在分析时考虑。

Sparkium · 渲染系统

从场景描述到图像输出，组织几何、材质、相机、灯光和不同渲染路径。

Core / Scene / Entity

场景与对象组织

Core 持有渲染公共资源，Scene 注册实体和渲染设置，Entity 将场景对象接入具体管线。

  • Core::Render 接收 Scene、Camera、Film 和渲染路径；ResolveRenderPipeline 返回自动选择或回退后的实际路径，供渲染和界面一致使用。
  • Scene 可添加、删除和启停实体，并维护稳定的注册顺序，用于实例 ID 和灯光采样。
  • Geometry 与 Material 分离：EntityGeometryMaterial 组合二者；EntityPointLight 提供点光源。公共着色器、缓冲和图像由 Core 统一提供。

适合：程序化场景、交互渲染器与多管线实验。

raster / raytracing

光栅与三种追踪路径

渲染路径包括显式光栅化、原生 RT pipeline、基于 ray query 的计算路径追踪，以及软件 BVH 计算回退。

  • 光栅管线拥有独立的场景、材质与几何实现。追踪路径共享 raytracing 系统中的相机、材质、灯光及采样逻辑。
  • auto 在 Vulkan / D3D12 支持 ray query 时优先使用它，否则依次考虑原生 RT、ray query 和软件回退；Metal 通常进入 ray query 或软件回退。auto 不自动选择光栅。
  • 显式请求原生 RT 但设备不支持时，可回退到 ray query 或软件；显式请求不可用的 ray_query 会报错。软件回退在 GPU 计算着色器中执行，不是 CPU 离线渲染器。

适合：不同 GPU 能力下的统一场景渲染。各管线支持的材质效果不保证完全相同。

GeometryMesh / GeometryHair

网格与发丝几何

几何对象将主机网格接入渲染系统，并由管线生成其需要的 GPU 表示。

  • GeometryMesh 承载三角网格，配合变换与材质构成可渲染实体；网格数据可来自程序生成或场景导入。
  • GeometryHair 接收控制点、半径和发束偏移，将各条发丝生成带法线和 UV 的管状三角网格；径向细分数决定网格精度。
  • 当前发丝通过网格表示参与渲染，不是硬件原生曲线 primitive，也不意味着已实现完整毛发散射模型。

适合：通用网格、程序几何与发丝形状预览。

Material / MaterialShaderGraph

材质、灯光与 Shader Graph

材质层包含 Lambertian、Specular、Principled 与发光材质，并支持由 JSON 节点图生成 Slang 表面参数计算。

  • 基础材质表达漫反射、镜面与发光行为；Principled 提供更丰富的表面参数。点光源实体与发光几何分别由对应灯光实现接入追踪系统。
  • MaterialShaderGraph 保存生成的代码、纹理引用和 emission hint；场景更新时安排纹理索引。具体可用节点由 JSON 导入和着色器生成代码决定。
  • 光栅与追踪分别实现材质适配。复杂节点图不应被理解为对外部 DCC 全部节点与渲染结果的无差别兼容。

适合：材质实验、纹理场景与 Blender 场景转换后的验证。

CameraPinhole / CameraThinLens

相机与景深

相机层提供针孔与薄透镜模型，前者用于清晰投影，后者在追踪路径中模拟有限光圈带来的景深。

  • CameraPinhole 提供基本透视相机；CameraThinLens 扩展焦平面和光圈相关参数，通过镜头采样形成离焦模糊。
  • 相机基础接口与各管线中的实现分开，渲染调用仍使用统一 Camera 对象。
  • Thin Lens 样例构建不同深度的物体，并提供交互参数和无窗口输出入口，可用于观察对焦与光圈变化。

适合：透视场景、摄影相机实验。薄透镜并不是完整多镜片光学系统。

Film

累积、色调映射与输出

Film 将渲染中的线性图像与最终显示分开，负责累积状态、重置与显示变换。

  • 保存原始图像、深度和 stencil 资源，并记录 accumulated_samples、persistence 和 clamping 等设置。
  • Develop 将图像转换到目标图像，包含曝光、gamma、contrast 与 view transform；线性 HDR 输出采用 linear sRGB 和扩展的 Filmic 外观。
  • Reset 及重置回调使场景或参数改变后可以清除累积。最终是否以 HDR 呈现还取决于 graphics 窗口和显示链路。

适合：渐进渲染、结果预览和 SDR / HDR 输出。

scene_io / Sparkium CLI & GUI

JSON 场景与工具链

JSON 场景入口把场景资源、模型、相机和渲染设置连接起来，CLI 与 GUI 复用渲染系统。

  • 场景格式与导入器在 scene_io 中维护；使用仓库的示例场景和格式文档作为字段、资源路径及支持类型的依据。
  • GUI 用于浏览场景、交互调参与图像观察；CLI 用于批量或无窗口渲染。Blender 对齐文档说明转换后的效果验证范围。
  • 模型、贴图、场景与报告图片集中存放在 assets LFS 子模块，主仓库固定其提交版本，便于复现实验。

适合：场景交换、自动渲染与回归对比。外部格式支持以导入器实际处理的字段为准。

Snowberg · 绘制与交互

面向应用的绘制、界面、可视化与求解组件；它们各有明确的数据和使用入口。

draw::Core / Model / Texture

二维绘制与字体

draw 提供命令式的模型、纹理和文本绘制，GUI 面板使用它绘制基础形状与文字。

  • BeginDraw / EndDraw 收集命令，Render 将其提交到指定图像。CmdDrawInstance 携带变换、颜色和可选纹理；CmdSetDrawRegion 设置绘制区域。
  • FontCore 管理字体数据；Core 支持字体文件、ASCII 字体、字号设置、文本宽度测量及文本绘制。
  • 绘制程序按目标 ImageFormat 缓存，模型与纹理通过底层 graphics 资源执行。它适合直接绘图，不负责通用应用布局。

适合：2D 覆盖层、文字、游戏自定义图形。

gui::Context / Theme / Canvas

面板、控件与玻璃合成

Context 每帧声明可见控件，并保留稳定 ID 对应的指针捕获状态。Theme 与自定义 Canvas 提供统一的外观和绘制入口。

  • 面板与行布局包含 Text、Heading、Button、Checkbox、整数/浮点 Slider、Choice、Plot、Spacer 和 Separator。Custom 返回指针响应并调用 Canvas 绘制回调。
  • Canvas 提供矩形、圆、文字与粒子场。EndFrame 接收场景图像，通过两遍背景模糊与合成得到玻璃面板效果；Theme 控制颜色、暗色风格和背景模糊。
  • WantsPointer 帮助应用协调界面与场景输入。当前通用键盘焦点、文本编辑和滚动裁剪仍不完整；粒子场是绘制能力，不是独立粒子模拟系统。

适合：渲染工具和调参面板。当前统一 GUI 实现随 PR #79 提供。

gui::WorldPanel

世界空间界面

WorldPanel 将同一个 GUI Context 用于 3D 场景中的平面面板。

  • 界面先绘制到离屏纹理，再作为场景中的四边形绘制，并参与深度测试，使它与 3D 物体具有遮挡关系。
  • 通过射线与面板相交计算局部坐标，再转为 Context 的指针输入；屏幕空间与世界空间面板可以在同一个样例中使用。
  • 它提供平面世界 UI 的渲染与命中能力。跨多个面板的输入优先级、相机射线和场景对象交互仍由应用组织。

适合：游戏内仪表、3D 控制面板。示例与接口见 PR #79。

gui::surface

保留自定义风格的游戏表面

surface 将 2048 和 GoL 原先重复的应用、输入、模型绘制、按钮及动画基础设施整合到共享模块。

  • Application 管理图形应用循环与窗口输入，DeviceModel 提供游戏网格数据的绘制基础，Listener / Button 承接事件和按钮交互。
  • AnimationVar 与插值工具维护动画状态；游戏可以继续提供自己的网格、着色器、字体和视觉逻辑。
  • 2048 与 GoL 保留原有布局、配色、图标、动画和操作。统一基础设施与 GUI 面板共处于 snowberg/gui，应用可选择合适的绘制入口。

适合：已有游戏 UI 迁移及高度自定义界面。新 surface 随 PR #79 提供。

visualizer::Core / Scene / Film

场景可视化

visualizer 提供可扩展的场景可视化渲染组织，拥有独立的相机、网格、实体、程序与图像资源。

  • Core 创建 Camera、Mesh、Scene 和 Film；Scene 注册 Entity，由实体在不同渲染阶段执行自己的逻辑。
  • 几何阶段写入 exposure、albedo、position、normal 与 depth 等通道，再执行光照阶段；相机数据通过缓冲传给着色器。
  • OwnershipHolder 按在途帧保留资源，并在命令执行完成后清理，避免渲染中的资源被提前释放。

适合：自定义实体和多通道可视化。现有管线骨架与资源管理已实现，具体可视化内容需实现 Entity。

solver::Scene / SceneDevice

粒子、形变与刚体求解

solver 管理粒子、拉伸/弯曲元素与刚体对象，并提供 CUDA 设备侧求解和状态查询入口。

  • ObjectPack 将粒子和约束成组加入主机场景；稳定 ID 通过目录结构映射到内部索引，刚体使用网格 SDF 数据。
  • SceneDevice 保存设备位置、速度、质量、约束和刚体状态，提供 Update / UpdateBatch，以及位置查询和刚体刚度、摩擦相关接口。
  • 设备实现受 __CUDACC__ 条件控制，主机数据接口的存在不代表 Metal 上拥有等价求解后端。

适合：CUDA 物理实验和批量场景更新。此处为源码能力说明，本轮文档更新未执行 CUDA 验证。

contradium::PBDSolver

Contradium · 刚体 PBD

当前具体实现是刚体 PBD 求解器：维护网格、SDF、位姿、质量、惯量与线/角速度。

  • AddEntity 创建刚体及其网格 SDF。Step 施加重力、预测位姿，通过顶点与对方网格 SDF 检测接触，再迭代修正位置和旋转。
  • 状态接口可设置位置、朝向、质量、惯量和速度。求解完成后由修正位姿更新线速度和角速度。
  • 现有算法使用成对对象和顶点检查、固定迭代次数与标量惯量，适合小规模实验；完整关节、通用动力学体系和大规模性能并未由此得到保证。

适合：简单刚体接触与 PBD 研究。应视为实验性求解器。

practium::Core / Scene / Entity

Practium · 仿真与渲染联动

Practium 将 Sparkium 渲染场景和 Contradium 求解器组织到同一个应用场景，连接物理状态与可见对象。

  • ModelMesh、MaterialPBDRigid 与 EntityPBDRigid 组成当前明确实现的网格刚体路径。Scene 按需要创建 PBDSolver，并注册实体。
  • Step 推进物理；SyncRenderState 将实体状态同步到 Sparkium。当前 Step 使用固定 0.01 秒步长，不应将声明中的 Settings 理解为已生效的通用调度器。
  • 现有 AddEntity 实现识别 PBD 刚体材质。更多实体类型、机器人控制和完整仿真框架还需继续扩展。

适合：简单物理场景的渲染联动，参考 practium_hello。

pybind11 / long_march

Python 与 CUDA 互操作

可选的 Python 绑定主要覆盖 Grassland graphics，让脚本使用核心图形对象与窗口接口。

  • 绑定包括 Core、设备缓冲、图像、采样器、着色器、光栅/计算/RT 程序、加速结构、命令上下文与 Window。
  • python 目录提供 Graphics Hello 系列、计算 NBody 和 Warp 相关样例。启用 CUDA 时可提供共享缓冲设备指针；依赖配置与硬件要求仍需满足。

适合：图形脚本、计算实验与 Python / GPU 协作。CMake 中不要禁用 Python 绑定。
